# Website Development — Phase-by-Phase Implementation

## Core Objective

Build the entire website by following the design reference images provided in the `Designreference` folder. Every section must closely match its corresponding reference in layout, spacing, typography, colors, visual hierarchy, and overall appearance.

The landing page must clearly communicate the product, its purpose, features, and value proposition so users can understand it without needing to explore other pages.

**Important:** Keep the design clean, minimal, and purposeful. Do not overdesign, add unnecessary elements, or introduce features that I have not requested.

---

## Phase 1 — Project Setup

**Tech Stack: Next.js**

1. Set up the complete project using Next.js before starting any UI development.
2. Use the App Router and a clean, maintainable project structure.
3. Configure the styling system and install only the necessary dependencies.
4. Ensure the project runs correctly before proceeding to Phase 2.
5. Keep the entire project within Next.js. Do not switch to another framework or create a separate frontend application.
6. Establish reusable components and consistent styling conventions where appropriate.

**Completion requirement:** Finish and verify the initial Next.js setup before beginning the hero section.

## Phase 2 — Hero Section

Build the hero section first.

### Information Source

Read and extract all relevant product information from `Myabout.md`. Use it as the primary source of truth for the product's identity, purpose, messaging, features, and value proposition.

### Design Requirements

* Follow the corresponding hero design reference in the `Designreference` folder as closely as possible.
* Use the actual product information from `Myabout.md`.
* Maintain the reference's layout, typography, spacing, colors, and visual hierarchy.
* Ensure the headline communicates the product's core value immediately.
* Keep the supporting description concise and understandable.
* Implement only the buttons, navigation elements, visuals, and other components indicated by the reference.
* Make the section responsive across desktop, tablet, and mobile screens.
* Use subtle animations only when supported by the reference or necessary to reproduce its intended behavior.

**Completion requirement:** Finish the hero section and verify its appearance and responsiveness before moving to the next section.

## Phase 3 — Build the Remaining Sections

After completing the hero section, implement the remaining website sections **one at a time and in the order specified by the design references**.

For each section:

1. Inspect the corresponding reference image in `Designreference`.
2. Identify its purpose, layout, content hierarchy, and visual elements.
3. Use `Myabout.md` and other relevant project information to determine the appropriate content.
4. Reproduce the reference's design as closely as possible.
5. Keep the content concise, clear, and easy to understand.
6. Ensure consistent typography, spacing, colors, and component styling across the website.
7. Implement responsive behavior without compromising the original design.
8. Test the section before proceeding to the next one.

Do not skip sections, combine separate sections without permission, or invent additional sections.

---

## Design Principles

### 1. Follow the References

The images in `Designreference` are the primary visual guidelines. Do not replace their design with your own interpretation unless a technical limitation makes it necessary.

### 2. Avoid Overdesign

* No unnecessary gradients, decorative elements, or animations.
* No excessive use of cards, borders, shadows, or background effects.
* No redundant content or repeated messaging.
* No additional sections or features without explicit instructions.

### 3. Prioritize Clarity

Every section should serve a clear purpose and help visitors understand the product.

### 4. Maintain Consistency

Use a consistent design system throughout the website while preserving the unique layout of each reference section.

### 5. Write Product-Focused Content

Use the information in `Myabout.md` to explain the product accurately. Do not invent unsupported features, claims, statistics, or capabilities.

### 6. Keep the Code Maintainable

Use reusable components where appropriate, sensible file organization, and clean, readable code. Avoid unnecessary abstractions and dependencies.

---

## Implementation Workflow

Follow this exact sequence:

**Step 1:** Inspect the project files, `Designreference` folder, and `Myabout.md`.

**Step 2:** Set up Next.js and verify that the application runs.

**Step 3:** Build and verify the hero section using the reference image and product information.

**Step 4:** Build the next section, verify it, and continue section by section.

**Step 5:** Once all sections are implemented, perform a complete review of the website for visual consistency, responsiveness, navigation, and functionality.

### Final Instruction

Work incrementally. Complete the current phase before moving to the next. Use the provided references and project files instead of making assumptions.

**The goal is not to make the website more elaborate than the references. The goal is to reproduce the intended design accurately while making the product exceptionally easy to understand.**
